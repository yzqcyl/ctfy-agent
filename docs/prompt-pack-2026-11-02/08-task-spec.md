## 五件具体的事

### T1 · 修掉"capstone 已内置"的假话（必做，最小改动）

两处：

- rev 第 23 行：`view=disasm → 反汇编指定偏移（offset/length/count；v4 镜像含 capstone，无引擎时自动退化字节视图）；`
- pwn 第 19 行：`...要看指令用 elfpeek view=disasm（offset/length/count，v4 镜像含 capstone，无引擎自动退化字节视图）；...`

事实：**v4 镜像没有 capstone；v5 起才有**（Dockerfile 已改，见 `09-baseline-diff.md`）。
要求：不再让模型以为"环境坏了"。可以让它知道"没有就退化成字节视图，别去 pip install"。

### T2 · 写清 `disasm` 的 offset 是文件偏移（必做，防 v5 爆雷）

`view=symbols` 的 `value` 列和 `view=info` 的 `entry` 都是 **vaddr**；`view=disasm` 的 `offset`
要的是 **文件偏移**。ET_EXEC 里两者差一个数量级（0x400440 vs 0x440）。
传错会直接抛 `offset=0x400440 超出文件长度 0x213d`，白烧一步。

v4 镜像里因为没 capstone，退化路径不做范围校验，所以这个坑现在不发作；v5 一装就会发作。
要求：在 rev/pwn 的静态段落里各加一句可执行的取数路径（"从 `sections` 的 offset 列取"）。

### T3 · 重写"工具分工"（本次最核心，可以大改）

**问题**：现有提示词把静态分析整段推给 `elfpeek`，但实测 63 次 rev 会话里
`shell` 619 次 vs `elfpeek` 106 次，只有 38% 的会话用过它。模型不是没看见，是权衡后不干。

要求：把"顺序执行 5 个视图"改成**两条明确的分工路线**，让模型知道什么情况下该写脚本：

- **单点精确结论**（某个函数在做什么、有没有某个符号、这个字符串在哪）→ 用 `elfpeek`，
  一次一个视图，快且不用写代码；
- **全量扫描 / 批量过滤 / 需要可编程中间结果**（1 MB 二进制里找散落常量、按偏移区间筛字符串、
  批量验证一个假设）→ **直接写 python 脚本**，一条命令跑完，不要拆成 5 次 elfpeek。
  提示词要**明确授权**这件事，现在它读起来像是"不许写脚本，只能调工具"。

注意：授权写脚本的同时，`07-constraints.md` 的注入防御（不可信数据、只访问下发实例）不能松。

### T4 · 补上 `relocs` / `dynamic` 两个新视图的用法（必做）

工具 schema 里已经有这两个视图（`04-tool-surface.md` 的 `elfpeek` 部分），但提示词的
"静态四步"里没提，模型不会主动想到用。它们解决的是以前只能手写 python 的问题：

| 视图 | 什么时候用 | 输出长什么样 |
|---|---|---|
| `relocs` | 判断静态还是动态链接；把 `printf` 映射到 `@0x601018`（即 `printf@got`）；看 PLT stub 顺序；反推 `.init_array` 构造函数 | 见 `05` 的 §relocs |
| `dynamic` | `NEEDED` 看链接哪个 libc；`RUNPATH/RPATH` 看随题分发的 `.so` 在哪；有 `BIND_NOW` = full RELRO = GOT 只读（别想 GOT 劫持）；`FLAGS_1` 的 PIE 位 | 见 `05` 的 §dynamic |

要求：在 rev 的静态段落加 2 行、pwn 的静态段落加 1–2 行，写清"什么信号触发用哪个视图"，
不要只写"有这个视图"。

### T5 · 清冗余（可选）

`UNAVAILABLE_RULE` 是**无条件追加**的（见 `03`），内容就是"不可达就收口，不要去翻本地文件系统"。
而 rev 正文第 12 行、pwn 正文第 12 行各有一句同义的话。

要求：合并，但**保留正文那半句里的 `netcheck`**（追加版没有工具名，正文版有）。目标是不重复、不丢信息。

## 一句实话：改完我们怎么验证

**现在没法 A/B。** 11-03 的 rev 池只有 3 道（解出 2 道），pwn 只有 1 道离线可跑。
样本量不足以区分"提示词改好了"和"运气好"。

所以这次改动的验收只能是**结构性**的：上面 7 条硬检查 + 一次小样本复跑（若预算允许）。
真正的效果确认要等评测池扩到 ≥8 道 rev / ≥5 道 pwn 之后。**这一点必须在动手前说清楚，
避免出现"改完测试全绿所以一定更好"的错觉。**
