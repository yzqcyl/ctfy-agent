  `download_challenge_attachment` 绕开了。

## 三、我们没照单全收的三处

| 编号 | 它写的 | 我们改成 | 为什么 |
|---|---|---|---|
| A | rev 硬约束仍是"别用 shell 引号硬拼"，同页又新增"小计算可直接 `python3 -c`" | 硬约束改"写文件用 write_file，别在 `python3 -c` 里 `open().write()`" | 引号守卫只在 Windows 生效（`tools_local.py:2584` 的 `os.name=="nt"`），容器里 `-c` 本来可用。原措辞把"禁止用 -c 写文件"写成了"禁止 -c"，和新增行直接打架 |
| C | `BIND_NOW=full RELRO` | 加"通常"（rev/pwn 各一处） | `BIND_NOW` 而无 `PT_GNU_RELRO` 只是 partial；我们自己的 `dynamic` 视图原文也是"**通常**"。pwn 历史 0 解，判错会把模型推去试 GOT 劫持死路 |
| D | 建议"若按 ±15% 从严就删掉 rev 那句 `python3 -c`" | 改我们的口径（`07 §八`），保住那句话 | ±15% 是行文提示，硬门是脚本的 1900–2600。删掉的正是解决 A 的那句，不能删 |

它的建议本身是善意的（怕超长），但**照做会把刚修好的矛盾退回去**——这属于"两个都对的口径冲突，
改文档比改内容便宜"。
