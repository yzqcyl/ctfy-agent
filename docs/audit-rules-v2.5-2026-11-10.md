### 1.2 计分

- 解题分：动态题值，初始 **1000**、下限 **100**，随有效解题队伍数 n 衰减（公式含指数项，**PDF 该行文本层缺字形**，精确式以官方口径为准；d = 该赛道参赛队伍数/3）。同分排序：score → flags_solved → **先解出者优先**（平台 ordering 实测）。
- 出题分：所出题在正式赛中的**最终动态题值**；未提交或**公开前验题失败记 0**；发布后**裁定无效按争议规则倒扣**；三轮加和。
- 最终 = 出题分 50% + 解题分 50%；初选赛解题分与正式赛解题分各占 50% 加权。未晋级队保留初选赛成绩、不进正式赛排名。
- 出题得分赛后人工审核后统一公布，平台显示值不一定是最终成绩。

## 2. P0-1：没有出题能力（最大缺口，占最终成绩 50%）

### 规则依据

- §一（P1）：「智能体赛道另设**出题环节**，审核通过的题目同时作为人机协同赛道正式赛的赛题。」
- §二(一)（P2）：入围测试「对智能体赛道团队的**解题/出题 Agent** 进行初步测试」——11/14 可能就下发，届时一 `refused` 就是「不支持」而不是少得分。
- §二(二)（P2）：出题三轮、主题主办方下发、**每轮最多 1 题**、Web/Pwn/AI Security（可同时考察两个方向）、各轮分别冻结提交/验证/审核、**未提交或未过审不发布且名额不得转移到其他轮次**、**同一道题不得重复提交**、材料平台封存跨夜。
- §二(四)（P3）：出题分与解题分**各占 50%**；发布后裁定无效**倒扣**。

### 现状

`grep -rn "authoring" src/ctfy_agent/*.py` → 0 命中；平台 MCP 有现成的 23 个出题工具（`get_authoring_template` / `check_authored_challenge` / `revise_authored_challenge` / smoke 族 / quota 族，见 `docs/mcp-tools.json`）。`241c845` 已把未知 `run_mode` 从「整题弃权」降级为「按通用解题链路跑」（`UNSUPPORTED_RUN_MODES` 只拒 defence/awd/engagement）——这是止损，不是能力。

### 出题流程必须满足的规则约束（给实现者的清单，别再漏）

1. **部署只用 §1.3 的 13 个白名单基础镜像**；依赖可从 **TUNA** 装（出题 Agent 网络白名单内有 TUNA）。
2. **六条禁止**（§二(六) P5–P6）：换皮预制题 / 纯猜测穷举 / 理论无解或题解-EXP 与部署不一致 / 依赖未公开秘密或隐藏通信 / 直接泄露 Flag、明显平凡、抄袭公开赛题、利用平台漏洞过验题 / 其他影响公平性。
3. **提交前必须自验**：平台有 `check_authored_challenge` + smoke 试运行（实测 `smoke_quota=10`、人工审核）。「零解或官方 Agent 未解出不单独作为无解依据」，但验题失败记 0 分、**发布后裁定无效倒扣**——宁缺毋滥，每轮只交 1 题时尤其如此。
4. **每轮 1 题、不重复提交、名额不跨轮转移** → 流程要按轮次状态机管理，别把三轮当一批。
5. **保密**：出题材料平台封存；**整体比赛结束前不得公开题解或 EXP**（见 #11）。
6. 赛段间更新要走「允许窗口 + 登记」（见 #14）。

### 建议

11/15 后的更新窗口出 v8：先用 `get_authoring_agreement`/`get_authoring_quota`/`get_authoring_template` 只读摸清下发形态（工单问清：出题任务是 run_mode、competition_id 还是纯 MCP 工具族），再实现「读主题 → 出题（三选一方向）→ 部署（白名单镜像+TUNA）→ 自验（check+smoke）→ 提交（每轮 1 题）→ 记录轮次状态」。

## 3. P0-2：正式赛 1B token + 智谱切换，我们只有单题刹车

### 规则依据

§二(五)（P3）：正式赛仅智谱 `open.bigmodel.cn/*`，Token 总量 1B；「不得通过代理、重定向、子进程或其他方式绕过网络和资源限制」。

### 现状与风险

- 只有单题 `max_tokens_per_challenge=800k` + `max_llm_calls=240`；`budget.py` 的 `Budget` 生命周期 = 一道题，无跨题累加。
- 量级上撞不上（1B / 800k = 1250 题·次），**实质风险是额度耗尽后无降级手段**（只会一道道 `halted`）。
- 新增（#6）：`agent_main.py` 优先读平台注入的 `LLM_API_KEY/LLM_BASE_URL/LLM_MODEL`，缺失时**回落 agent.json 的百炼地址**——正式赛无公网，回落链路会全挂，表现为「每题都在 LLM 调用上失败」，**开赛后 10 分钟才发觉就废掉一段**。

### 建议

1. 全局累加器先不做（平台没有额度查询接口就别造）；做**降级链**：预算耗尽 → 单题上限自动减半重试，而不是弃题。
2. `max_tokens_per_challenge` 视 11/14 实测吞吐从 800k 调到 400k 左右（现有中位数远低于 800k）。
3. **11-21 开跑前人工核查平台注入的 `LLM_*` 指向 bigmodel**（「状态查看」是规则允许的人工动作）；低成本代码兜底：rollup 里加一条「LLM_BASE_URL 不在正式赛白名单」的告警字段。
4. 智谱切换不改代码：`.env`/平台注入换 `LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4` + GLM 模型名即可；`enable_thinking` 的 400 风险已修（#4）。

> **2026-11-12 状态更新（P0-2 全局账本已落地）**：新增 `src/ctfy_agent/gledger.py`，在
> `DeepSeekLLM.chat()` **发请求前** `check()`、收到响应后 `record(usage)`；按平台计费口径的
> **原始 token**（prompt+completion，不减缓存折扣）跨题/跨进程累加，落盘
> `<CTFY_WORK_DIR 或 runs 上一级>/.ctfy-global-ledger.json`；上限 `config.max_total_tokens`
> 默认 **1B**（`AGENT_MAX_TOTAL_TOKENS` / `CTFY_MAX_TOTAL_TOKENS` 可覆盖，0=关闭）。
> 到顶抛 `BudgetExceeded(kind="budget_exhausted")`，现有 retry/报告链条无需改动即正确收口
> （不会继续白烧额度）。开跑时 transcript 落一行 `[全局总账] 已用/上限` 供事后核对；
> 回归 `tests/smoke_gledger.py` **19/19**。设计说明见 `docs/global-token-ledger.md`。
> 原先「建议 1：全局累加器先不做」作废——平台虽无额度查询接口，但本地记账足以在到顶时停手。

> ✅ 同一条里做对的：入围/初选我们用的 `dashscope.aliyuncs.com/compatible-mode` **精确命中白名单**（§1.3 第 3 家）；`config.py` 默认回落 `api.deepseek.com` 也在白名单内。

## 4. P1-5 / P1-6 / P1-7（人工确认与流程项）

### #5 双赛道报名（唯一「做错即出局」项，5 分钟）

### #6 正式赛 LLM 注入核查

见 §3 建议 3。

### #7 本队题目得分规避

§二(三)（P3）：「出题队伍及本队关联身份队伍**不得通过本队题目得分**。」平台大概率自己过滤计分，但我们的解题 Agent 在 11-22 会照啃本队题**白烧预算**。需要确认平台下发时怎么标记本队题（题面 author 字段？还是不下发？），能在题单过滤就过滤；不能就靠预算刹车兜底。**出题功能做完之前这条无解**（没有「本队题」概念），先挂账。

### #10 出题约束清单

已并入 §2「出题流程必须满足的规则约束」，不重复。

### #11 公开仓库/镜像的保密边界

规则原文（P3/P6）：「所有出题材料由平台封存，**整体比赛结束前不得公开题解或 EXP**」「整体比赛结束及 WP 截止前，不得公开题解或 EXP」「11-21 出题材料跨夜封存，不得通过人工或越权通道传入其他解题环境」。

我们的暴露面：镜像名 `ctfy-agent-pub` 暗示公开；git remote `github.com/yzqcyl/ctfy-agent`；`runs/` 已 gitignore ✓，但 **`docs/` 已提交的复盘文档里有练习场 flag 字样**（DASCTF 练习场重签发 flag，泄露无实质危害，但 11-21/22 期间把正式赛题的任何分析 push 上去就是违规）。**流程约定：11-14 起到整体比赛结束，任何含赛题分析/EXP/出题材料的内容不进公共仓库、不进公共镜像**；出题材料只走平台封存通道。

### #12 平台漏洞处置义务

§五(四)（P7）：「发现平台漏洞应**及时向主办方报告**，不得借此获利。」我们历史上真找到过平台毛病（MCP 信封、`additionalProperties` 拒参等）。给协调者提示词加一句纪律：发现疑似平台漏洞 → 记录、停止利用、转人工申报；顺手把这条写进出题六条禁止的对照（「利用平台漏洞通过验题」本来就是禁止项）。

### #13 题量未知 + 每段 10h 的吞吐

`challenges_withheld=true`：11-15 开赛才知道题量。若 >40 题，单题平均不足 15 分钟，`max_steps=12` + 800k + `deadline` 都要按 11-14 实测吞吐重标。这不是规则违规，是**规则造成的运营约束**。
