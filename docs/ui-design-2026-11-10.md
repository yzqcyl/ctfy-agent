# GUI 视觉改版（毛玻璃 / GitHub 配色）—— 实现说明 · 2026-11-10

> 范围：`src/ctfy_agent/gui/`（tkinter 桌面端，**不是网页**）。容器镜像不含 GUI，改动只影响本地操作界面，
> 不触碰 `platform.py` / `solver.py` / `cli.py` / `agent_main.py` 的任何行为。
> 校验入口：`PYTHONPATH=src python -m ctfy_agent.gui.app --selftest` → `GUI selftest OK`。

## 1. 规范的落地方式

需求给的是 CSS 口径（毛玻璃、Inter 字重字距、rgba 阴影、`cubic-bezier` 过渡）。Tk 没有 CSS 引擎，
所以把每条规范翻译成「画布绘制 + 定时器动画」：

| 规范原文 | 落地实现 |
|---|---|
| 毛玻璃态（Glassmorphism） | `theme.Card(glass=True)`：玻璃白 `#FBFCFD` + 1px `#E5E7EB` 边框 + 双层浅阴影。Tk 无真正高斯模糊，用「低对比填充 + 边框 + 阴影」近似 |
| GitHub 配色 | `theme.py` 顶部令牌：页面 `#F6F8FA`、卡片 `#FFFFFF`、文字 `#1F2328`/`#57606A`、主色 `#0969DA`（hover `#0550AE`）、语义色 成功/危险/警告 |
| 标题 Inter Bold，正文 Inter Regular | `theme.heading_font()` / `theme.body_font()`；字体栈 Inter → 系统无衬线 → 中文回退（微软雅黑 UI/苹方），`pick_family()` 负责挑第一个可用 |
| 大标题字距 -0.02em；标题行高 1.2~1.3，正文 1.5~1.7 | `LETTER_SPACING_EM=-0.02`：Tk 字体没有 letter-spacing，标题在 Canvas 上**逐字绘制**并按 `字号×-0.02` 收字距（`_draw_brand`）。行高以常量 `LINE_HEIGHT_HEADING/BODY` 记录，供多行文本手工排布 |
| 浅阴影 `0 1px 3px rgba(0,0,0,.05), 0 1px 2px rgba(0,0,0,.1)` | `Card` 在画布上先画两层错位圆角矩形（`SHADOW_1`/`SHADOW_2`），等价于该 CSS 阴影的观感；`SHADOW_CSS` 常量保留原文便于核对 |
| 过渡 `all 200ms cubic-bezier(.4,0,.2,1)` | `TRANSITION_MS=200` + `make_easing(0.4,0,0.2,1)` 的贝塞尔求解（牛顿迭代），`RoundedButton` 悬停/按下用 `after(16ms)` 逐帧插值 |
| 加载状态：骨架屏脉冲 / 旋转指示器 | `theme.Skeleton`（脉冲 1.2s，扫「已解出」列表与题库列表）+ `theme.Spinner`（连接平台 / 扫描中） |
| 按钮：圆角 8px、内边距 12×24、字重 500、悬停上浮 2px 并加深、按下缩放 0.98 | `RADIUS_BUTTON=8`、`PAD_BUTTON=(24,12)`、`BUTTON_FONT_WEIGHT=500`、`HOVER_LIFT_PX=2`、`PRESS_SCALE=0.98`；变体 primary/secondary/ghost/danger/success 各自算 hover/press 颜色 |
| 卡片：白底、圆角 20px、1px `rgba(0,0,0,.05)` 边框、图片区半透明渐变 | `RADIUS_CARD=20`、`BORDER_SOFT=#F2F2F2`（= 0.05 黑叠白的精确合成值）、`overlay_gradient()` 提供图片/横幅区的渐变覆盖（当前界面无图片位，留作扩展） |
| 输入：圆角 12px、背景 `#F9FAFB`、聚焦 2px 主色、placeholder `#9CA3AF` | `theme.RoundedEntry`：`RADIUS_INPUT=12`、`SUBTLE` 底、聚焦重绘 2px `PRIMARY` 描边、placeholder 用 `PLACEHOLDER` 色且 `get()` 不返回占位文案 |
| 图标：Feather/Heroicons 风格、20×20、颜色继承文字色 | `theme.icon()`：15 个矢量图标（`ICON_PATHS`）按 20×20 视口缩放绘制到 Canvas，`color` 默认取当前按钮文字色 |
| 分隔线：1px `#E5E7EB`，也可用渐变透明线 | `theme.Divider(fade=True)`：用 `mix()` 画 1px 渐变线（两端淡出），默认色即 `BORDER` |

## 2. 界面结构

```
窗口（GitHub 页面底色）
├─ 毛玻璃标题条 Card：Canvas 逐字绘制的品牌标题（-0.02em）+ 副标题 + 状态胶囊 + 耗时/预算 + 设置
├─ 预算卡 Card：token / 调用数两条 Progressbar + 费用
└─ 左右分栏 PanedWindow
   ├─ 左栏（ScrollFrame，整栏可滚动，带细滚动条）
   │  ├─ 模式卡：离线靶场 / 平台接口（单选框卡片态）
   │  ├─ 表单卡：离线表单（地址/题型/难度/题名/题面/运行名/已起靶确认） 或 平台表单
   │  │   └─ 平台表单：档案 → 连接 → 比赛 → 刷新题单（骨架屏）→ 题库勾选 →
   │  │      跑题库选项（跳过/重跑已解出）→ 运行名 → 并发度
   │  ├─ 任务历史卡：Listbox + 细滚动条 + 刷新/查看/续跑/删除
   │  └─ 固定页脚：开始 / 停止（离线、平台各一套，随模式切换；不随内容滚动，永远可见）
   └─ 右栏 Notebook
      ├─ 复现：按日期分层的「已解出」表格 + 复现正文（骨架屏/转圈）
      ├─ 任务面板：动态列 Treeview
      ├─ 日志：单一日志区（原「工具流/过程」两页签并入，避免三份重复输出）
      └─ 底部：复制 flag / 复制复现稿 / 导出报告
```

## 3. 三个功能性需求

1. **跑题库可选「跳过已解出 / 重跑已解出」**
   - UI：平台表单「跑题库」两个单选框（`var_skip_solved`，默认跳过）。
   - 判定：读 `runs/<run-id>/state.json` 里 `challenges[*]` 的 `submitted_ok` 或非空 `flag_value`（`_solved_cids_for_run`）。
   - 行为：`_start_platform` 用 `theme.filter_solved()` 过滤，日志打印被跳过的题号；若全被跳过则弹「无需重跑」并中止（不白烧预算）。
   - 勾选统计实时提示：`已勾选 N 道 · 其中 M 道已解出（将跳过/将重跑）`。
2. **题目复现栏按日期分层**
   - `theme.group_by_date()` 把已解出条目按 `updated_at`（缺失则用目录 mtime）分到 `YYYY-MM-DD`，倒序、同日保序、无法解析的归「未知日期」。
   - Treeview 改 `show="tree headings"`：日期是父节点（`2026-11-10 · 3 题`），题目是子节点；选中也要选到题目行才算数（选到日期行会提示）。
3. **未显示完的界面加滚动条**
   - 左栏整体用 `theme.ScrollFrame`（内容超视口即出现细滚动条，滚轮只在该栏生效，不影响右侧表格）。
   - 「开始/停止」放在左栏**固定页脚**（不随内容滚动）：平台表单内容比离线长一倍，按钮也不会被挤出视口。
   - 题库列表、已解出列表、任务面板、复现正文、日志、历史列表各自带垂直滚动条。

## 4. Tk 能力边界（做不了 / 折中）

- **没有真正的背景模糊**：毛玻璃用「低对比玻璃白 + 细边框 + 阴影」近似。
- **不能把子控件裁剪成圆角**：`Card` 的圆角只作用于自身背景与边框；内部的 Treeview/Text 用 1px 细边框面板（`theme.panel()`）保证直角不显突兀。
- **字体没有 letter-spacing**：只在品牌大标题上逐字绘制；正文保持系统排版。
- **没有逐帧合成/GPU 动画**：过渡用 `after()` 定时器插值（16ms/帧、200ms 全程）；窗口销毁时自动取消定时器。
- **表格行高/单元格圆角不可控**：交给 ttk 主题统一样式（`apply()` 里配置 GitHub 配色与 Inter 字体）。

## 4.1 字体清晰度（DPI）

原来 `tk scaling` 硬编码 1.2，在 150% 缩放的屏幕上等于「Tk 按 1.2 画 → 系统再把整窗位图放大 1.5 倍」，
所以字又大又糊。现在：

1. `theme.enable_dpi_awareness()` 在建 Tk 窗口**之前**声明 Per-Monitor V2（失败退 Per-Monitor / System Aware）；
2. `theme.apply_dpi_scaling(root)` 取真实 DPI 设 `tk scaling = (dpi/72)*0.9`：96dpi 仍是 1.2（老机器观感不变），
   144dpi 变 1.8 —— 等效像素比与旧版一致，但由 Tk 直接按物理像素渲染，字是锐的；
3. 像素尺寸（表格行高/列宽、左栏宽度）改用 `theme.ui_px()` 换算，避免「字号变大、行高没变」把字挤扁；
   表格行高按字体 linespace 动态计算，正文用 11pt、表头 10pt 粗体。

## 4.2 页签（复现 / 任务面板 / 日志）

ttk.Notebook 的页签做不到「选中蓝底白字、未选中白底深字、彼此留空隙、圆角」，所以换成自绘
`theme.TabBar`（`nb.body` 给页面当父容器，`add()`/`select()` 与 Notebook 同名）：

- 选中：主色 `#0969DA` 填充 + 白色文字；未选中：白色填充 + 深色文字 `#1F2328`；
- 页签之间留 8px 空隙、圆角 10px，不再互相紧贴；
- 切换只做 `grid()`/`grid_remove()` + 提高层级，页面状态不丢。

## 4.3 任务面板「用时」与「已解出（跳过）」

- 旧实现每个 tick 对**所有行**重算 `now - started`，所以已解出的题会一直走表。现在行记录里带
  `finished`：第一次进入终态（已解出/已解出（跳过）/未解出/已取消/出错）时记下停表时刻并把用时定死，
  tick 跳过已停表的行；重新开跑同一题（状态回到「解题中」）会重置起点。
- 「瞬间出现一堆已解出」的真相：`Crew.solve` 默认有**两层已解出预检**（本地 state 的 `submitted_ok` /
  平台 `my_solved_ids`），命中就零成本返回，所以看起来是「秒解、0 token」。这类结果现在由 worker 标记
  `presolved`，界面显示**已解出（跳过）**并在日志里注明「已有解出记录，未重烧」，与真正跑出来的「已解出」区分开。
- 要真的重跑：GUI 把「重跑已解出」勾选项换算成 `force_ids` 传给 `platform_worker.solve_many`，后者对
  这些题调用 `Crew.solve(force_rerun=True)`，**跳过两层预检**（默认 False，CLI/其它调用行为逐字不变），
  日志会打印「强制重跑已解出 N 道（忽略平台/缓存已解记录，会真实消耗 token）」。

## 4.4 任务面板的「轮次 / Tokens / 花费」

平台批量路径走 `Crew.solve`，而它原先只发 `budget_plan`，不发 `budget` / `step` —— GUI 正是用这两类事件
刷新面板的，所以三列永远停在 `0 / 0 / -`。现在 `Crew.solve` 补齐：

- 开跑时发一次 `budget`（基线，含历史累计）；
- 每轮协调结束发 `step`（轮次 +1）和 `budget`（最新 tokens / calls / cost）；
- 收口时再发一次 `budget`，保证最终数字落在面板上。

花费列显示规则：`agent.json` 的 `price_input/output_per_mtok` 都是 0（默认）时等于没配单价，花费恒为 0，
显示 `-` 并在开跑日志提示「填了单价后自动按 token 计价」；配了单价就显示 4 位小数。

## 4.5 滚动条（三张表都有上下 + 左右）

- 题库、已解出、任务面板三张表都改成 grid 布局：`Treeview + 竖滚动条 + 横滚动条`，列宽固定不 stretch，
  长题名 / 长详情 / 整段 flag 超宽时拖横条看全，不再被硬截断；行数超出拖竖条。
- 顺手修掉一个**所有滚动条都看不见**的老问题：ttk 滚动条的厚度由样式 `arrowsize` 决定，之前设了
  `arrowsize=0` → 控件退化成 1px。现在 `arrowsize=ui_px(11)`（高 DPI 下约 16px），箭头颜色配成底色，
  视觉上是一条干净的细滚动条；测试里连「厚度 ≥ 8px」一起断言。

## 4.6 设置对话框（含两个子弹窗）

- 主界面同一套视觉：毛玻璃标题条、圆角胶囊页签（平台档案 / 模型 / 预算：选中蓝底白字、未选中白底深字、
  圆角 10px、间距 8px）、白色卡片分区块、`RoundedEntry`（12px 圆角 + 聚焦主色边框，Token/API Key 支持 `show="*"`）、
  主题圆角按钮（新建/重命名/删除/恢复、自动生成映射、一键接入、测试连接/保存/取消）。
- **尺寸自适应**：先按页内容期望尺寸算窗口大小，再夹进屏幕 90%（小屏/高 DPI 都不会超出屏幕）；
  窗口可缩放，缩小时每页走 `ScrollFrame` 出滚动条，内容不会被裁掉。
- 子弹窗（自动生成工具映射、一键接入）用同一套背景/按钮/文本框与主题色，尺寸也按 DPI 换算。

## 5. 兼容性约束（刻意保持不变）

- 所有原有控件属性名不变（`lbl_status`、`bar_tokens`、`tv`、`tv_solved`、`btn_start_p`、`nb` …），事件处理逻辑未改；
- `theme.RoundedButton` 兼容 `ttk.Button` 的 `config(state=/text=/command=)`、`cget()`、`invoke()`；
- `theme.TabBar` 兼容 `Notebook` 的 `add(page, text=)` / `select(index)` 用法；
- `python -m ctfy_agent.gui.app --selftest` 仍输出 `GUI selftest OK`；
- 纯标准库：`theme.py` 只依赖 `tkinter`，预览工具在没有 Pillow 时回退存 BMP。

## 7. 已知限制 / 后续

- 「已解出」判定以 `runs/<run-id>/state.json` 为准；换 run-id 跑同一批题视为全新一轮（历史 run 的已解出不会迁移）。
- 若平台题单里同一题号跨 run 复用，跳过逻辑只看当前运行名对应目录，符合「重跑整轮」的语义，但不适合「跨轮续跑」场景——需要时再按 challenge id 聚合所有 run。
- 强制重跑不重置「该题历史累计 token」：预算仍是同一口锅里的剩余额度，额度不够时该题会以「预算不足」收口（这是账本语义，不为了让重跑跑起来而篡改用量）。
- 「花费」需要配单价：`price_input_per_mtok` / `price_output_per_mtok` 默认 0，未配置时花费列显示 `-`（不显示误导性的 0.0）。
- 没有暗色主题（规范只要求 GitHub 浅色）；`theme.py` 的令牌集中，后续加暗色只需再加一组常量与切换入口。
