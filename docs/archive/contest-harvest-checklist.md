# 比赛收割 Checklist（三段 session：11-15 / 11-21 / 11-22，各 10:00–20:00）

> 依据：docs/archive/report-large-scale-test.md 的实测教训（§9.2 平台记忆效应、§11.1 实例配额坑、
> §10 预算=调用次数）+ docs/archive/plan-p2v-validation-and-alignment.md §4.3。
> 用法：每段比赛照此从上往下过，打勾留痕。

## 0. 开段前 15 分钟（不动实例）

- [ ] `runs/_preflight_instances.py` → **必须 0 实例**（非 0 先清理，绝不带残留开段）
- [ ] 拉 `my_solved_ids()` → 本队已解清单入账本；**已解出题绝不重跑**（预检短路=0-token 假解出，污染统计）
- [ ] 确认镜像 tag（提交物用显式 `:vN`，禁 `latest`）
- [ ] 载入 dead-end 账本（上段判死的题不回头）
- [ ] 统计工具就位：`python runs/_stats.py <批目录>`（任何数字只认它）

## 1. 开场 10 分钟：全库扫描排序

- [ ] 拉全库题元数据 → 排序键：**已解队数↓ → 难度 → 我方工具面覆盖**（web > crypto/文本 > pwn/rev）
- [ ] 标记三类：A=立即做（已解队多+我方强域）、B=中段做、C=hard（余量>50% 才开）
- [ ] 出题日（11-21）authoring 任务单独排队，不与解题抢实例

## 2. 主循环（每题）

- [ ] 实例用**驱动代拿**（慢速退避 start → 预注册 → 复用），agent 不自己起实例；**不高频重试 start**（被拒的 start 可能异步建出实例泄漏占配额）
- [ ] 预算分层：easy/medium `--cap 300000`，hard 才给 500k
- [ ] **拿到候选 flag 立即提交**（同分先解出者胜，不追求最优利用链）
- [ ] 失败即记 dead-end（原因 + 已试路径），换题不回头
- [ ] 每题结果行落 `runs/<batch>/*.jsonl`（驱动自动），人工只补备注

## 3. 段中每小时：预算纪律

- [ ] 跑 `_stats.py` 看全局：剩余预算 / tok-per-completed 趋势 / 解出率分域
- [ ] 解出停滞 >2h 且全在 hard → 回 B 类题收割
- [ ] 实例配额异常（start 连续被拒）→ 停批清实例再继续，不硬冲

## 4. 收段前 1 小时

- [ ] 不再开新题（剩余时间不够一次完整尝试）
- [ ] **清空全部实例**（配额释放，不留坑给下一段）
- [ ] `_stats.py` 出全段报告 → 数字记入 docs（口径：tok/solve 主、解出率+Wilson 次）
- [ ] dead-end 账本 + 已解清单持久化

## 5. 分段差异备忘

| 段 | 模型/key | 特殊事项 |
|---|---|---|
| 11-15 初赛(QA) | **自备**国内模型 key（百炼，`LLM_ENABLE_THINKING=0`） | 验证容器端到端即算赢；顺手验 P2-2 未验项 |
| 11-21 正式赛 D1 | 官方智谱 1B token | **authoring_enabled=true 要出题**，authoring 流程独立；智谱端点对 `enable_thinking` 字段兼容性提前确认 |
| 11-22 正式赛 D2 | 官方智谱 | 收割为主；段末留 30min 清理+复盘 |

## 6. 禁止事项（全部吃过亏）

1. ❌ 重跑已解出题（0-token 假解出，统计全废）
2. ❌ 高频重试 `start_instance`（实例泄漏自我强化，两批 11/11 题作废的教训）
3. ❌ 留实例过夜 / 带残留实例开段
4. ❌ 用 `latest` tag 提交
5. ❌ 手算解出率进文档（只认 `_stats.py`）
6. ❌ hard 题吃掉 easy 题的预算（开场排序的意义就在这）
