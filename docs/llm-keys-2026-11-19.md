## 2. 自动切换机制（三层）

| 层 | 文件 | 触发 | 动作 |
|---|---|---|---|
| ① 开盘前预检 | `/root/comp/precheck_llm.sh`（cron 09:50 / 09:57） | 当前 key 打 `/chat/completions` 非 200/400 | 切 fallback（改 `repo/.env` 三行） |
| ② 运行中监控 | `/root/comp/llm_watch.sh`（cron 每 2 分钟） | driver.log/events 里鉴权/额度类错误累计 ≥6 | 切 fallback + 重启比赛容器（run-id 不变，已解出跳过，断点续跑） |
| ③ 手动 | `/root/comp/switch_llm.sh primary\|fallback` | 人工 | 改 env 三行；容器在跑则自动重启续跑 |

切换只改三行：`DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL`；
每次切换前自动备份 `repo/.env.bak.HHMMSS`；切换后可用
`PYTHONPATH=src python3 -c "from ctfy_agent.config import load; c=load(); print(c.llm_base_url, c.model)"` 核对。

**注意**：换端点必须同时换模型名——百炼侧模型 `deepseek-v4.1-flash-1017` 在 DeepSeek 官方不存在，
官方对应 `deepseek-flash`（已实测可用）。只换 key 不换模型会 404。

## 3. 为什么不用 key pool 混装两把 key

`LLM_API_KEYS` 池是按「同端点轮换」设计的；两把 key 属于不同厂商/端点，混进池子会把
DeepSeek 官方 key 发给百炼端点（或反之），必然 401。因此主备按**整套端点+模型**切换，
而不是 key 池轮换。
