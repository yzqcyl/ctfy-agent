**这一批暴露并当场修掉的 4 个 bug（提交 `8fccaa5`）**：

1. **按题参数映射**：ctf2 schema 是 `additionalProperties:false`，只认 `practice_ground_id/challenge_id/limit`；但 `practice_ground_id` 服务端又必填。
   旧写法「塞 `competition_id`」会被拒、「只传 challenge_id」报缺必填 ⇒ 自愈路径**恒静默失效**。
   修法：`instance_guard._challenge_args()` 按目标工具 schema 只传它认的字段，并把已知比赛 id 映射成 `practice_ground_id`。
2. **工具级软失败**：MCP 的工具错误是 `----- 工具返回 (isError=true) ----- {"code":"NOT_FOUND",…}` 文本，`call_text()` **不抛异常**。
   旧 `delete_environment` 把删除失败当成功 → 白重试一次 start。修法：`_tool_failed()`。
3. **`NOT_FOUND` 白重试**：给没有环境的题（crypto/misc）start 必回 `NOT_FOUND`，旧逻辑照样「删环境+重试」。
   修法：`solver._start_failure_worth_recycle()`，只有槽位/配额类失败（`agent_environment_limit`/rate limit/conflict/quota…）才回收重试。
4. **跨 run 沙盒污染**：每个 run 的沙盒都在 `runs/<run>/sandbox/`，旧 run 残留（含官方仓库占位 `flag.txt`）会被新 run 的 shell 读到并被当答案提交。
   修法：`tools_local._cross_run_guard()` 拒绝任何引用**其它 run** 沙盒的 shell 命令 + `COORDINATOR_PROMPT` 写明「工作目录只有本题沙盒」。

## 4. 关键机制（改代码前必看）

1. **参数桥接**（`gui/platform_adapter.py`）：按目标工具 `inputSchema` 自动翻译参数名；对 CTFY 这类同构平台是 no-op。GUI 开跑前 `_seed_bridge()` 预置比赛/练习场 id。**CLI 不装适配层**，所以 DASCTF 上要用 GUI 或 `platform_worker.solve` 的驾驶脚本。
2. **实例三道防线**（`instance_guard.py` + `solver.py`）：开跑前清扫（有 `list_instances` 才有意义）→ start 前记账（每题 5 次硬上限）→ start 失败自愈（按题查/删环境）。安全边界：`keep` 本题不碰、`protect` 兄弟题不碰、拿不到时间/年龄 <120s 不碰（宁可漏杀）。
3. **附件自动下载**（`attachments.py`）：`_dig_envelope` 按 `structuredContent → content[].text` 拆 MCP 信封；练习场要用 `ctf2_get_practice_challenge`（比赛变体要 `stage_id`，用错不报错只是没有 files[]）。
4. **重复被拦动作断路器**（`crew.py`）：同一 `(tool,args)` 连续被拦 2 次摘出工具面，4 次以 `reason=action_loop` 收口（映射平台 `max_turns`）。
5. **预算三层**：`max_llm_calls`（agent.json=240）、`max_tokens_per_challenge`（800k）、`deadline_minutes`（时间刹车，GUI/驾驶脚本可设）。`Budget` 按「计费 token」算，缓存命中部分打折。
6. **本地第三方库外挂**（`tools/fetch_pylibs.py` → `tools/pylibs/`，gitignore）：已装 pycryptodome / gmpy2 / sympy / **z3-solver / pwntools**（2026-11-12 补齐）。`shell()` 子进程自动挂 `PYTHONPATH` 与 `*.libs` 的 DLL 目录；**agent 进程内**由 `src/ctfy_agent/pylibs.py` 接入（append 到 `sys.path`，缺库静默退化），并新增三个工具：`z3solve`（SMT-LIB2 求解）、`pycrypt`（AES-GCM/CFB/OFB/EAX/CTR、3DES）、`pwnrop`（checksec/plt-got/ROP 链）。详见 `docs/pylibs-bridge.md`。
   注意：本机 Windows 开了 Smart App Control，会拦未签名原生模块（z3 的 `libz3.dll`、pycryptodome 的 `_raw_ecb`/`_raw_ctr`、gmpy2），所以 **z3/GCM 在本机进程内不可用**（工具会提示「原生模块被系统策略拦截」）；Linux 镜像/WSL 正常。本地功能验证走 `tests/_libs_linux_probe.py`（WSL venv）。

## 7. 雷区（本轮新增的排前面）

### 平台侧（本轮新增）
- **工具级错误是软失败**：判断「写操作成功与否」必须扫回执文本（`isError=true` / `code` / `NOT_FOUND`），不能只看有没有抛异常。
- **ctf2 schema 严格**（`additionalProperties:false`）且 `practice_ground_id` 必填；参数桥接层能靠「失败一次再补」学到它，但别依赖调用顺序。
- **`attempt` 全局计数**：跨 run 重跑会提前耗掉平台提交次数；本地 store 只记本次 run。
- **实例回执无 id**：只有 `access_url`；实例失效自愈在 ctf2 上不会触发。
- **自动起实例对所有题型都会试一次**：crypto/misc 这类没环境的题会白烧 1 次 start 配额（实测 `NOT_FOUND`）。未修，见 §8。
- **公开 flag 必被判错**（练习场重签发 flag）。

### Windows 本地（沿用上一轮）
- PowerShell **5.1**；`.ps1` 必须 UTF-8 BOM+CRLF；`.cmd` 必须 CRLF；`%TEMP%` 不可写。
- **`tempfile.mkdtemp()` 在本机建出的目录连自己都读不了**（POSIX 0o700 在 Windows 上失效）：临时目录用 `runs/` 下普通 `mkdir`，装包用 `tools/fetch_pylibs.py`。
- `runs/` 里有历史不可读 `pip-*` 目录：遍历 `runs/*` 要逐目录 `try/except OSError`。

### 代码约定
- 主链路 `platform.py` / `solver.py` / `cli.py` / `agent_main.py`：**不做破坏性改动**；本轮只做了两处小增量（`_recover_instance_slot` 追加分支、`max_llm_calls_source` 记录），都有回归。
- 新能力优先放新文件，或对实例打补丁（`platform_adapter.install` 的思路）。
- 密钥只进 `.env`；`config/platforms.json`、`runs/`、`tools/pylibs/` 都不进 git。
- 真实解题 = 烧额度 + 起容器，**必须先问用户**；只读 connect/list/查环境可以随便跑。
