## 0. 现状一句话（TL;DR）

项目原本是「**容器镜像 + 平台 MCP 接口**」的赛题 agent（见 HANDOFF.md）。本轮追加了一条**不依赖任何平台接口**的用法：
**人给目标地址 + 题型 + 难度，agent 自主打、产出 flag，窗口可视化操作**（GUI）。

同时把「换平台/接新平台」从**手工填工具名**升级为**连上平台自动读契约、自动生成映射、自动体检**，
并修掉了 Windows 本地跑时的一批环境适配问题。

**当前可用**：离线靶场（人工起靶）、平台接口（CTFY / DASCTF 练习场）、单题/批量/并发、按需复现稿。
**当前短板**：CRYPTO / PWN 基本没开张（缺依赖库 + 平台环境配额），详见 §8。

> **2026-11-10 接手轮（W）复核后的状态（以本节为准，数字均有出处）**：

## 1. 十分钟跑起来

### 1.1 环境

- Windows + 解释器：`%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe`（3.12.x）
- 项目根：`E:\ctfy_project`，源码在 `src/`，**代码本身纯标准库**（无第三方依赖，无需 pip install）
- 但 ctf 脚本常要 `Crypto`/`gmpy2`/`sympy`：可选装到 `tools/pylibs`（见 §8.1），shell 工具会自动挂载；镜像里没有该目录，行为退回纯 stdlib
- 设 `PYTHONPATH=src` 后可直接 `python -m ctfy_agent ...`

```powershell
Set-Location E:\ctfy_project
$py = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
$env:PYTHONPATH = 'src'
```

### 1.2 图形界面（本轮主要交付物）

```powershell
cmd /c "E:\ctfy_project\run_gui.cmd"      # 无控制台黑框启动
```

- 入口：[run_gui.cmd](run_gui.cmd) → [run_gui.pyw](run_gui.pyw) → `src/ctfy_agent/gui/app.py`
- 出错会写 `runs/gui-error.log`（正常启动不会产生该文件）

## 2. 两种使用方式（操作视角）

### 2.1 离线靶场（人工起靶，不接平台）

1. 模式选「离线靶场」
2. 填目标地址（每行一个）、题型、难度
3. 点「开始」

内部实现：`OfflinePlatform`（[offline.py](src/ctfy_agent/offline.py)）冒充平台对象，
把目标 URL 注册进本地工具白名单，复用同一套 Crew 流程；引擎入口 [hunt.py](src/ctfy_agent/hunt.py)。

### 2.2 平台接口

1. 模式选「平台接口」→ 选平台档案 → 「连接平台」
2. 选比赛/练习场 → 「刷新题单」→ 勾选题目（支持全选/全不选）
3. 设并发度（自动按硬件/平台上限夹紧）→ 「开始」

### 2.3 窗口结构（本轮重构过，3 个页签）

| 页签 | 内容 |
|---|---|
| **复现** | 左：**已解出题目列表**（题目/分类/flag/运行名）；右：选中后**按需生成**该题复现稿 |
| **任务面板** | 动态表：题目 / 状态 / 详情 / 轮次 / Tokens / 花费 / 用时 |
| **日志** | 原「进展 + 工具流 + 过程」三合一 |

- 「停止」按钮是**双模**：`立即停止`（掐断正在解的题）/ `解完再停`（不再开新题，等当前题跑完）
- Flag 候选不再单独占页签，直接进「复现」页（列表有 flag 列）

## 5. 关键机制（为什么这么写）

### 5.1 参数桥接 `platform_adapter.py` —— 本轮最重要的设计

**问题**：平台工具名对上之后，**参数名往往还不一样**。以 DASCTF 练习场实测为例：

```
list_challenges  要 practice_ground_id，我们发的是 competition_id
get_instance     根本没有 instance_id，要 practice_ground_id + challenge_id
submit_flag      要 flag + confirmation(=true) + practice_ground_id + challenge_id
且这些工具 additionalProperties=false —— 多传一个字段就报错
```

**做法**：给平台实例**打补丁**（`platform.call` + `platform._as_json`），按目标工具的 `inputSchema` 通用地做四件事：

1. 别名改名（`competition_id → practice_ground_id`、`flag → answer` 等）
2. 记住事实（见过的 id 值，后续缺必填时自动补）
3. 补 `const` 必填（如 `confirmation=true`）
4. `additionalProperties=false` 时丢弃 schema 不认识的字段

**为什么打补丁而不是改类**：`call_text` / `call_raw` / 高层方法 / 模型直接调工具**最终都走 `self.call`**，
一处挂载即可全覆盖，且 `platform.py` 一行不用改 → CLI 主链路零风险。对 schema 本就吻合的平台（CTFY）是纯 no-op。

附带修的一致性问题：
- 返回值单键包装解包（`{"challenge": {...}} → {...}`，否则题目名/描述全取不到）
- 实例**就绪轮询**（`starting → running` 通常要 1~2 分钟，原实现只查一次就再也不问）
- 轮询可被「立即停止」打断（用 `Event.wait` 而非 `sleep`，实测 120s → 0.21s）

### 5.2 工具映射自动生成 + 一键接入

- 映射算法 [toolmap.py](src/ctfy_agent/gui/toolmap.py)：词干归一（`challenges→challenge`）+ 加权打分 + 比赛/练习场模式偏好
- 「一键接入」[onboard.py](src/ctfy_agent/gui/onboard.py)：读 `tools/list` → 两种模式各生成一套映射 →
  用「实际能取到多少数据」择优 → 只读实测（列表→题单→题目详情）→ 逐个动作体检（OK / 缺工具 / 需参数）
- **关键性质**：生成的映射只可能由**真实存在的工具名**构成，从根上消灭「手填/OCR 出错名」这类事故
- 兜底路径（无 token 只有截图时才用）：图片 OCR → 可编辑列表 → 人工校对；应用时还会连平台校验纠正

### 5.3 实例与端点（容器类题型）

平台就绪后返回的是**裸 `host:port`**（如 `xxx.tcp-ctf2.dasctf.com:9999`），且常带 `nc_ssl: true`（需 TLS）。
`tools_local` 的端点登记已支持裸 `host:port` / 裸主机名；`tcp` 工具的 TLS 提示也已修（见 §4）。

### 5.4 Windows shell 兼容层

- 守卫改为**只扫描双引号之外**的字符（`python -c "print('x')"`、`print(1 << 2)` 在 cmd 里完全合法，原来被误拒）
- 实测误拒率：CTFY 历史 **73/116 = 63%**，DASCTF 本次 **90/100 = 90%**
- 自动改写：`python3→python`、单引号→双引号（仅在不含 `% ! ^` 且无嵌套双引号时）
- 仍会拒绝并给建议：`sed/awk`、引号外单引号、引号外 heredoc

### 5.5 ffuf 降级兜底（**不是等价替代**）

本机没有 ffuf 二进制时启用 [ffuf_shim.py](tools/shims/ffuf_shim.py)（CLI 完全兼容，`tools_webscan.py` 主流程不改）。

| 支持 | 不支持 |
|---|---|
| GET + URL 处 FUZZ、`-mc` `-fs` `-fc` `-fr` `-e` `-ac`、并发、`-maxtime` | 递归、POST/头部 fuzz、多字典/多关键字、`-mr/-fw/-fl`、限速、HTTP/2、代理 |

实测吞吐（本机回环）：约 1400 req/s（15 线程）；无 keep-alive，打远程会明显低于真 ffuf。
**结论**：是「让 web 侦察从不可用变为可用」的兜底，note 里会明确告知模型这是降级扫描。

### 5.6 双模停止

- 立即停止：`cancel` 置位 → 正在解的题被掐断（含打断实例轮询）
- 解完再停：`graceful` 置位 → **不再开新题**，等当前题跑完
- `solve_many` 改为**增量提交**（原来一次性把全部任务丢进线程池，优雅停止拦不住）

### 5.7 复现按需生成

「复现」页只读 `runs/*/state.json` 列出已解出题，**不点不生成**（不消耗任何 LLM 调用）。
生成时只解析该题自己的 transcript（`writeup.py` 支持 `challenge_id` 过滤）。

## 9. 雷区（踩过的坑，别重踩）

### Windows 本地

- PowerShell 是 **5.1**：不支持 `? :` 三元、`??`
- `.cmd` 必须 **CRLF + ASCII**（LF 会导致 `ModuleNotFoundError`）
- `.vbs` 会被杀软干掉、`.lnk` 被 App Control 策略拦 → 只能用 `.cmd`
- `%TEMP%` 在受限环境不可写 → 临时文件放工作区 `runs/_gui_tmp`
- cmd 里的 `python` 可能落到应用商店占位符 → shim 统一走 `CTFY_PYTHON` 环境变量
- PowerShell 读 UTF-8 无 BOM 文件会按 ANSI 解析 → 用 `[System.IO.File]::ReadAllText(path, UTF8)`
- **`.ps1` 必须 UTF-8 带 BOM + CRLF**：PS 5.1 把无 BOM 的中文注释按 GBK 读，会报「`","`后面缺少表达式」「Try 语句缺少 Catch」这类假语法错。`tests/smoke_ps1.py` 会检查每个 `.ps1` 的 BOM/换行，并用 `Parser::ParseFile` 真解析
- `run.cmd` 等 `.cmd` 用 **CRLF**（`.gitattributes` 已钉 `*.cmd`/`*.ps1` = `text eol=crlf`）；LF 检出会直接 `ModuleNotFoundError`
- **`tempfile.mkdtemp()` 在本机建出的目录连自己都读不了**：这个 Python 构建在 Windows 上仍按 POSIX 用 `os.mkdir(..., 0o700)`，之后 `chmod` 报 `WinError 5`。`pip install --target` 就是因此报 `Permission denied: …pip-unpack-*`。解：`tools/fetch_pylibs.py` 把 `mkdtemp` 补成 0o777 并把 TEMP 指到工作区；自己写脚本时也**别**用它，直接在工作区 `mkdir`
- **`runs/` 里有历史遗留的不可读 `pip-*` 目录**（上面那条的产物，31 个）。任何遍历 `runs/*` 的代码都要逐目录 `try/except OSError`（`gui/app.py` 已按此改）

### 平台侧（本轮新增）

- **DASCTF 的工具回执是 MCP 文本信封**：`{"content":[{"type":"text","text":"<JSON 字符串>"}],"structuredContent":{…}}`。`platform._as_json()` **只吃字符串**，喂 dict 会抛 `AttributeError` 被吞掉 → 上层拿到整个信封、`files[]` 一律为空。解析要按 `structuredContent → content[].text` 顺序拆（`attachments._dig_envelope`）
- **`get_challenge` 在不同模式不是同一个工具**：练习场是 `ctf2_get_practice_challenge`，正式比赛是 `ctf2_get_competition_challenge`（后者还要求 `stage_id`）。用错那个查练习场题**不报错、只是没有 files[]** → 会得出「题目没有附件」的假结论。附件模块因此有兄弟工具回退（最多 3 个，只在没取到附件时才试）
- **`agent_environment_limit` 的语义**：练习场和正式赛环境**共用一个配额**，起新环境前必须先删旧的；`instance_guard.reap()` 的宽限期默认 120s，就是为了别误杀并发兄弟题
- **DASCTF ctf2 没有 `list_instances`**（2026-11-11 只读实测）：`instance_guard.reap()` / `solver._find_live_instance()` 在这条平台上永远返回空，**别以为开跑前清扫生效了**。只有两个按题原语：
  `ctf2_get_environment(practice_ground_id, challenge_id)` → `{"environment":{"access_ready":false,"status":"none"}}`（无环境时 `status="none"`；桥接层会自动补 `practice_ground_id`）；
  `ctf2_user_delete_practice_id_challenges_challengeid_environment`（按 challenge_id 删，不需要实例 id）。跨题残留因此无法在本平台清扫（见 §8.2）
- **公开仓库/样例里的 flag 交上去必然判错**：练习场是重新签发的 flag。11-10 那批「7 题答案被拒」全是这么来的（`winxy-pistol`/`vorpal-sword` 的仓库文件自己写着 `repo placeholder`）。判错的回执是 `{"accepted":false,"attempt":1,"submission_id":…}`——**不是格式拒收**，别去改前缀/拼写重交
- **MCP 工具级错误是「软失败」**：`platform.call_text()` 只在传输层失败时抛异常；工具自己报错时回执正文里是 `----- 工具返回 (isError=true) ----- {"code":"NOT_FOUND",…}`。任何「写操作是否成功」的判断都必须自己扫这段文本（`instance_guard._tool_failed`），否则会把失败当成功
- **ctf2 的参数 schema 是 `additionalProperties:false`**：按题工具只认 `practice_ground_id`/`challenge_id`/`limit`，多塞字段会被校验拒绝；而 `practice_ground_id` 又是服务端**必填**。参数桥接层能靠「失败一次再补」学到它，但**别依赖调用顺序**——显式映射（`instance_guard._challenge_args`）
- **平台提交次数按「用户+题」全局计数**：本地 `store` 只记本次 run 的 attempts。跨 run 重跑同一题时，平台回执的 `attempt` 会比本地大（实测 1 vs 2）
- **ctf2 实例回执没有 id**：只有 `access_ready/access_type/access_url`，`instance_id` 为空（`_maybe_recover_instance` 因此不触发）
- **每个 run 的沙盒互相可见**（都在 `runs/<run>/sandbox/`）：旧 run 的残留（含从官方仓库下载的占位 `flag.txt`）会被新 run 的 shell 读到，模型会误当成平台下发值提交。`tools_local._cross_run_guard` 已确定性拒绝这类命令（2026-11-11 实测踩到）

### 代码约定

- **不要改** `platform.py` / `solver.py` / `cli.py` / `agent_main.py` 的既有行为（平台赛主链路）
- 新能力放新文件，或对实例打补丁（参考 `platform_adapter.install`）
- 密钥只进 `.env`；`config/platforms.json`、`.env`、`runs/` 都不进 git
- 不要用真实平台跑「解题」做验证（会起容器、烧额度）；只读的 connect/list 可以
